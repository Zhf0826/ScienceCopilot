ScienceCopilot

小学科学教师智能助手 · LLM · Prompt · Agent · RAG

← 返回应用

ScienceCopilot 把"小学科学备课"这件重复性高、专业门槛不低的工作， 交给一个会规划、会查课标、能评估实验安全的 AI Agent。它不是一个只会 补全文本的聊天框，而是一个由 LLM + Prompt Engineering + Agent 工作流 + 知识库 RAG 共同驱动的备课协作者。

我们要解决什么问题

小学科学教师（尤其非理科背景或新教师）在备课时常面临三件事：① 不确定 某个知识点在课标中的准确表述与年级对应；② 容易踩中学生的"直觉误区"； ③ 设计动手实验时缺乏系统性的安全评估。ScienceCopilot 用 AI 把这三件事 前置到生成与审核环节自动完成。

AI 能力的四层设计

LLM

OpenAI 兼容接口，默认 DeepSeek；负责最终的自然语言生成与推理。

Prompt Engineering

角色设定 + 约束 + 固定【栏目】输出格式，保证结果结构化、可解析。

Agent 工作流

ReAct 风格循环：规划 → 调用工具 → 观察 → 反思 → 产出，而非一次补全。

知识库 RAG

检索课标核心概念与常见误区，让生成"有据可依"，并透明展示来源。

Agent 是怎么工作的

当用户提交需求后，编排器（Agent）并不会立刻"凭空写答案"，而是先规划： 需要核对课标概念吗？涉及动手操作要评估安全吗？随后它调用两个工具—— retrieve_curriculum（RAG 检索）与 check_safety（安全检查）， 把工具返回的证据（observation）纳入推理，最后才产出符合格式的方案或审核结论。 每一步"思考 / 调用工具 / 观察"都会在前端以推理轨迹呈现，用户可以 清楚看到 Agent 为什么这样回答。

知识库 RAG 是怎么工作的

知识库 kb/curriculum.json 收录了小学 3-6 年级核心科学概念、常见误区与 年级对应；kb/safety.json 收录实验安全红线规则。检索采用关键词 + 年级 匹配的稀疏检索——这样做的好处是：无需 embedding 服务即可完全离线运行， 且检索结果对用户完全透明、可追溯。前端"RAG 检索来源"区块会列出命中的主题、 适用年级与命中关键词。后续可无缝替换为向量检索，对外接口不变。

技术栈与工程取舍

  • 零依赖：仅用 Python 标准库，python app.py 即可启动。
  • 离线可演示：未配置 API Key 时进入演示模式，RAG 与安全工具仍为真实调用。
  • 模块化：config / llm / rag / tools / agent / prompts / app 职责分离。
  • 可观测：统一返回 {trace, retrieved, safety, result, demo}，便于调试与评测。

快速开始

直接运行（演示模式，离线可用）：python app.py 后打开 http://127.0.0.1:8000。
接入真实模型（DeepSeek）：$env:DEEPSEEK_API_KEY="你的 Key" 后再运行。

面试讲解要点

  • "为什么是 Agent 而不是单次补全？"——因为备课需要查证与多步推理。
  • "RAG 为什么用稀疏检索？"——离线、透明、零依赖，且接口可平滑升级到向量。
  • "演示模式有何意义？"——让评审无需密钥即可完整体验系统，降低上手门槛。
  • "如何保证质量？"——固定输出格式 + 工具证据 + 可扩展的 LLM-as-judge 评测。

路线规划

MVP 加固 → 单 Agent（规划 + 工具 + 反思）→ 多 Agent 协作（设计/审核/安全三 Agent） + 向量 RAG + 记忆层 → 评测集与 Trace 面板 + 一键部署。
